# 需求与验收标准

## 用户、问题与目标

用户是内容运营人员。素材信息与审核结果分散，人工排期容易忽略风险、时段占用和重复操作。目标是在给定素材、规则、已有排期与用户时间要求下，为每项素材返回可核验的处理结果，并保存草稿。

业务成功标准：审核通过且有可用授权时段时保存确认草稿；信息不足时明确缺口；规则风险时阻断；冲突时查询替代时段并待用户确认；同一请求重复执行不增加草稿；保存失败如实报告。

## 范围

包含 CLI、本机网页与 HTTP API、可选双 Agent、合成 JSON 资料、本地工具、SQLite、真实模型工具调用、离线模拟、执行上限、Trace 与测试。支持同一请求内多素材顺序处理，保留已完成素材结果。

不包含发布能力、线上部署、多用户账号身份认证、真实内容平台审核、分布式调度、草稿删除/改期工作流。固定合成日期用于可重复评审；本原型不检查是否已超过现实当前时间。

每个整点时段代表一个发布机会，同平台容量为 1；不模拟视频播放时长或跨时段资源占用。批量输入不做全局最优排序。时段候选仅在同一天查找，跨日变更需要用户提供新要求。

## 不可突破的业务约束

1. `requested_slot` 为硬性要求。替代建议必须保留原要求，未经用户明确提供 `approved_slot` 不可成为已确认时段。
2. 待确认草稿 `reserved_slot=null`，不抢占时段；确认后必须重新审核与检查冲突。
3. 审核未通过、字段不足或时段未经查询，保存工具拒绝执行。
4. 保存成功来自数据库提交结果，模型文字不构成保存证据。
5. 幂等键为 `(request_id, material_id)`。同键更改原始时间要求报错；确认替代时间更新同一行。重复旧输入不能撤销已有确认。
6. 草稿没有发布能力，所有输出的 `published=false`。
7. 达到整个请求的模型调用上限时，未结束项返回 `incomplete / step_limit`；已保存的草稿不回滚、不隐瞒。

## 验收矩阵

| 验收点 | 输入或事件 | 必须可观察的结果 |
| --- | --- | --- |
| 正常排期 | M01，19:00 可用 | 审核通过、同一时段草稿保存、未发布 |
| 信息缺失 | M03 无 rights 且无补充资料 | 补查后列出缺口，无草稿 |
| 规则风险 | M04 含禁止声明 | 风险原因明确、阻断、不保存 |
| 时段冲突 | M01 要求 18:00，占用；19:00 可用 | 建议 19:00、待确认、原要求不变 |
| 重复提交 | 同请求与数据库运行两次 | 一行草稿、相同 ID、duplicate=true |
| 保存失败 | save_draft 注入故障或数据库拒绝写入 | failed、无虚报成功、事务无残留 |

扩展验收：资料补查成功、人工复核、用户确认后更新原稿、占用变更、无可用时段、暂时读取失败、执行上限、批量部分成功、并发保存竞争。

工程测试证明这些约束；模型决策质量须另用真实 API 执行上述输入，检查模型是否根据工具返回改变动作。Mock 不能替代这项验收。
