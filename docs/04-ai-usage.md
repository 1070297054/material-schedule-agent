# AI 使用披露

## 本版本的真实分工

本项目由用户要求 AI 助手直接实现。**当前代码、测试、合成数据、说明文档与示例生成脚本主要由 Codex 编写和执行。** 用户提供考核规范、创建并网页上传 GitHub 仓库、完成本机 GitHub 授权、指定 DeepSeek `deepseek-flash` 并提供模型接入配置。尚未记录用户亲自修改代码或独立运行测试的事实。

不能把本文件或其他文档中的实现取舍当作候选人已经独立完成的工作。真实模型测试由 AI 助手使用用户授权的 API 执行，实际记录见 `examples/live/`。候选人的个人代码修改、独立验证和学习收获需要在实际完成之后补充。

| 工作 | AI 使用范围 | 当前已验证的部分 |
| --- | --- | --- |
| 题目选择与设计 | 分析约束、选择第 1 题、设计单模型循环和事务边界 | 对照题目列出验收矩阵 |
| 工程实现 | 编写 Python CLI、本机网页/HTTP、角色交接、工具、模型适配、SQLite 存储 | 自动化测试、离线运行与真实 DeepSeek 调用 |
| 数据与案例 | 编写完全合成的素材、规则与排期 | 输入与输出在 examples 内可复现 |
| 测试与修复 | 编写业务/协议/CLI/并发测试；修正确认回退、评估假通过、保存错误契约不一致 | 测试日志与修复前后真实 Trace 均保留 |
| 文档 | 生成需求、方案、评估与复盘初稿 | 与当前代码及实际结果对应 |
| 接口核对 | 查阅 OpenAI 与 DeepSeek 官方 Responses 文档 | 协议替身测试、真实 deepseek-flash 评估 |

## 本次 AI 辅助交互摘要

1. 用户提供四道考核题与统一交付要求，询问选题。
2. AI 建议素材审核与排期，强调确认边界、去重及动态工具决策。
3. 用户授权直接实现项目。
4. AI 在空仓库实现代码和文档，运行测试，生成离线验收证据。
5. 用户指出真实模型验证缺口，指定 DeepSeek；AI 接入后运行真实评估，保留首轮 17/18 的失败记录，修正保存故障语义并复测。

开发过程没有使用 Codex 子 Agent；项目自身新增了审核/排期两个模型角色，不能混淆两者。没有把 ChatGPT/Codex 会话本身当作此项目真实 API 调用证据，没有读取用户登录令牌来替代项目 API 密钥。

## 候选人提交前需要如实补充

| 记录项 | 当前状态 |
| --- | --- |
| 候选人亲自实现/修改的模块 | 待实际完成后填写 |
| 修改前后的问题与行为变化 | 待实际完成后填写 |
| 候选人独立运行的命令、结果、日期 | 待实际完成后填写 |
| 候选人能够解释的技术取舍 | 需自行复核；不得默认已经掌握 |
| 实际个人投入时间 | 未记录，不能用 AI 执行时间替代 |
| 真实模型名称、运行记录、失败分析 | deepseek-flash；AI 执行记录见 docs/03-evaluation.md 与 examples/live/ |

建议亲自尝试一次有意义的变更，例如增加“同一平台两次发布至少间隔一小时”的业务规则，并用改变占用数据前后的真实模型记录验证影响。只有实际完成后，才把该工作写为个人贡献。

后续扩展由用户要求增加本机界面和多 Agent，并明确不要部署服务器。AI 实现、执行测试和真实双 Agent 验收，用户提出跨天多平台设计与安全问题；设计记录在 07-scaling-design.md，尚未实现该扩展。
