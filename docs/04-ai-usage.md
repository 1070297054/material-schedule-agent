# AI 使用披露

## 本版本的真实分工

本项目采用作者主导、AI 辅助实现的方式。作者负责制定项目架构方案、技术选型、代码 Review 与问题排查；AI 辅助完成方案细化、代码实现、测试执行及文档整理。以下作者贡献依据作者本人提供的说明记录。

### 作者贡献

- **制定项目架构方案**：确定项目业务目标与实现范围，规划审核、排期与任务规划角色的职责，以及跨天、多平台任务的协作方向。
- **技术选型**：参与确定本机运行方式、模型服务及工程实现方案，结合考核要求评审技术取舍。
- **代码 Review 与问题排查**：审阅实现与验收结果，围绕动态决策、确认边界、防重复、跨天恢复和安全防护提出问题并推动改进。

### AI 辅助范围与验证归属

**当前代码、测试、合成数据、文档与示例生成脚本主要由 Codex 编写和执行。** AI 参与架构方案细化和实现取舍，不能将这些产出描述为作者独立编码完成。用户另提供考核规范、GitHub 仓库与本机授权，指定 DeepSeek `deepseek-flash` 并提供模型接入配置。

真实模型测试由 AI 助手使用作者授权的 API 执行，实际记录见 `examples/live/`。自动化测试、真实模型评估和浏览器验收归属于 AI 执行的验证；作者的代码 Review 与问题排查不等同于独立运行这些测试。未声明作者独立编写或执行全部代码与测试。

| 工作 | AI 使用范围 | 当前已验证的部分 |
| --- | --- | --- |
| 题目选择与设计 | 分析约束、选择第 1 题、设计单模型循环和事务边界 | 对照题目列出验收矩阵 |
| 工程实现 | 编写 Python CLI、本机网页/HTTP、角色交接、工具、模型适配、SQLite 存储 | 自动化测试、离线运行与真实 DeepSeek 调用 |
| 数据与案例 | 编写完全合成的素材、规则与排期 | 输入与输出在 examples 内可复现 |
| 测试与修复 | 编写业务/协议/CLI/并发测试；修正确认回退、评估假通过、保存错误契约不一致 | 测试日志与修复前后真实 Trace 均保留 |
| 文档 | 生成需求、方案、评估与复盘初稿 | 与当前代码及实际结果对应 |
| 接口核对 | 查阅 OpenAI 与 DeepSeek 官方 Responses 文档 | 协议替身测试、真实 deepseek-flash 评估 |

## 本次 AI 辅助交互摘要

1. 用户提供四道考核题与统一交付要求，询问选题。
2. AI 建议素材审核与排期，强调确认边界、去重及动态工具决策。
3. 用户授权直接实现项目。
4. AI 在空仓库实现代码和文档，运行测试，生成离线验收证据。
5. 用户指出真实模型验证缺口，指定 DeepSeek；AI 接入后运行真实评估，保留首轮 17/18 的失败记录，修正保存故障语义并复测。

开发过程没有使用 Codex 子 Agent；项目自身提供审核/排期双角色与规划/审核/排期三角色，不能混淆两者。没有把 ChatGPT/Codex 会话本身当作此项目真实 API 调用证据，没有读取用户登录令牌来替代项目 API 密钥。
